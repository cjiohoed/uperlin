# 🔥 Perlin Flame — эффекты на ESP32

Генерация органических LED-эффектов (пламя, северное сияние, молнии, кометы и другие) на одномерной адресной ленте WS2812B с помощью целочисленного шума Перлина. Оптимизировано для ESP32 на MicroPython с использованием `@micropython.viper` и прямого доступа к буферу `neopixel`.

Проект портирует библиотеку [GyverLibs/uPerlin](https://github.com/GyverLibs/uPerlin) (основанную на FastLED) с C++ на MicroPython. Все вычисления — целочисленные, вывод визуально идентичен оригиналу.

---

## ✨ Возможности

- **15 палитр** — от классического огня до северного сияния и неона
- **10 эффектов** — пламя (3 варианта), искры, комета, радуга, сияние, пульс, молнии, светлячки
- **150 комбинаций** — меняйте две строки в `config.py`, чтобы получить новый эффект
- **Нативный шум Перлина** — портированы 1D и 2D версии (8-битный вывод `0..255`)
- **Viper-ускорение** — в 10–30 раз быстрее обычного MicroPython
- **Прямой доступ к `strip.buf`** — обход Python-обёртки `strip[i] = (r,g,b)`
- **Без пересборки прошивки** — правите `.py`, запускаете, видите результат
- **Низкое потребление CPU** — ~4–8% при 150 LED и 30 fps
- **Модульная архитектура** — алгоритм, палитры, эффекты и конфиг независимы
- **Встроенный бенчмарк** — замер скорости шума и кадра прямо в REPL
- **Автоопределение порядка байтов** — GRB/RGB через `strip.ORDER`

## 🧰 Требования

### Аппаратное обеспечение
- **ESP32** (любая ревизия: WROOM, WROVER, S2, S3, C3 — все Xtensa/RISC-V)
- **Адресная LED-лента** на базе WS2812B (или аналог: SK6812, WS2811)
- **Блок питания** с запасом по току: ~60 мА на LED при полной яркости
- **Резистор 330–470 Ом** между пином данных ESP32 и DIN ленты (рекомендуется)
- **Конденсатор 1000 мкФ** между +5V и GND ленты (рекомендуется)
- **Level shifter 3.3V → 5V** для линии данных (рекомендуется, ESP32 выдаёт 3.3V)

### Программное обеспечение
- **MicroPython** для ESP32, версия **1.20+** (нужна поддержка `@micropython.viper` и атрибут `neopixel.buf`)
  - Скачать: https://micropython.org/download/ESP32_GENERIC/
- Библиотека `neopixel` (входит в стандартную прошивку MicroPython)
- **Никаких сторонних зависимостей** — всё работает на чистом MicroPython

## 📦 Установка

### 1. Прошивка ESP32 MicroPython

```bash
# Стереть флеш (опционально)
esptool.py --chip esp32 erase_flash

# Прошить MicroPython
esptool.py --chip esp32 --port COM3 write_flash -z 0x1000 ESP32_GENERIC-*.bin
```

Замените `COM3` на ваш последовательный порт (Windows) или `/dev/ttyUSB0` (Linux/macOS).

### 2. Загрузка файлов проекта

Используя `mpremote` (рекомендуется):

Или вручную — через Thonny, VSCode с Pymakr, или любой другой инструмент для работы с файловой системой MicroPython.

## ⚙️ Конфигурация (`config.py`)

Все настройки — в одном файле. Меняете здесь, ничего больше не трогаете.

### `EFFECT` — выбор эффекта

Одна из функций из `effects.py`. Список — в разделе [«Эффекты»](#-эффекты).

### `PAL` — выбор палитры

Один из объектов из `palette.py`. Список — в разделе [«Палитры»](#-палитры).

### `NUM_LEDS` — число светодиодов

| Ошибка | Что будет |
| :--- | :--- |
| Занизить | Последние LED не горят |
| Завысить | Первые N работают, остальные мигают/гаснут |

**Разумные значения:** `30`, `60`, `144`, `150`, `300`

### `DATA_PIN` — GPIO линии данных

| Пины | Комментарий |
| :--- | :--- |
| 5, 13, 14, 16–19, 21–23, 25–27, 32, 33 | ✅ Подходят |
| 6–11 | ❌ Заняты flash |
| 34–39 | ❌ Только входы (input-only) |
| 0, 2, 12, 15 | ⚠️ Работают, но могут влиять на загрузку |

### `X_SCALE` — масштаб вдоль ленты

| `X_SCALE` | Ячеек на 150 LED | Как выглядит |
| :--- | :--- | :--- |
| `60` | ~0.14 | Одна очень широкая волна |
| `200` | ~0.5 | Широкая волна с вариациями |
| `400` | ~1 | Один язык на всю ленту |
| `800` | ~2 | Два-три языка |
| `1500` | ~3.5 | Четыре-пять языков (рекомендуется) |
| `3000` | ~7 | Много мелких языков |

> ⚠️ Значение по умолчанию `60` даёт «однородное» пламя без выраженных языков. Для реалистичного огня увеличьте до `800–1500`.

### `TIME_STEP` — скорость эволюции

| `TIME_STEP` | Эффект |
| :--- | :--- |
| `1` | Естественное «дыхание» (рекомендуется) |
| `2` | Активное движение |
| `5` | Быстрое, «кипящее» |
| `10+` | Хаотичное, для «взрыва» |

### `FRAME_MS` — частота кадров

| `FRAME_MS` | FPS | Когда использовать |
| :--- | :--- | :--- |
| `50` | 20 | Экономно, для ESP8266 или длинных лент |
| `33` | 30 | Баланс (рекомендуется для контражура) |
| `20` | 50 | Плавнее, для прямого взгляда |
| `16` | 60 | Максимум для глаза |

### `BRIGHTNESS` — общая яркость

| `BRIGHTNESS` | Эффект |
| :--- | :--- |
| `0.3` | Приглушённое «тление» |
| `0.6` | Сбалансированное (рекомендуется) |
| `1.0` | Максимум — обычно избыточно |

> ⚡ Ток потребления ≈ `NUM_LEDS × 60 мА × BRIGHTNESS`. Для 150 LED при `1.0` — до **9 А**. Убедитесь, что блок питания справляется с запасом ×1.5.

### `DEBUG_TIMING` — диагностика

| `DEBUG_TIMING` | Что делает |
| :--- | :--- |
| `True` | Бенчмарк при старте + fps каждые 2 с |
| `False` | Тихий режим |

## 🎨 Палитры (`palette.py`)

15 готовых таблиц `bytes` (256×3 R,G,B), генерируются один раз при импорте.

| Палитра | Характер |
| :--- | :--- |
| **`FIRE`** | Классическое огненное пламя: чёрный → красный → оранжевый → белый |
| **`ICE`** | Холодное синее газовое пламя |
| **`ARCANE`** | Зелёное магическое |
| **`PLASMA`** | Розово-фиолетовая энергия |
| **`TOXIC`** | Кислотно-зелёное радиоактивное |
| **`BLOOD`** | Багровое адское пламя |
| **`AURORA`** | Северное сияние: зелёный → голубой → фиолетовый |
| **`SUNSET`** | Закат: оранжевый → розовый → пурпур |
| **`OCEAN`** | Глубина океана: тёмный синий → голубой → белый |
| **`GOLD`** | Золотой янтарь |
| **`GHOST`** | Призрачное бело-голубое |
| **`VOLCANO`** | Тёмная кора с раскалёнными трещинами |
| **`CANDLE`** | Мягкое свечение свечи (низкая максимальная яркость) |
| **`NEON`** | Электрический неон: фиолетовый → пурпурный → белый |
| **`RAINBOW`** | Полный спектр радуги — только для `rainbow_flow`! |

### Как создать свою палитру

Добавьте функцию в `palette.py` по образцу существующих:

```python
def _build_my_palette():
    pal = bytearray(256 * 3)
    for v in range(256):
        # ваша логика: v → (r, g, b)
        if v < 128:
            r, g, b = v * 2, 0, v
        else:
            r, g, b = 255, v - 128, 255 - (v - 128)
        pal[v*3], pal[v*3+1], pal[v*3+2] = r, g, b
    return bytes(pal)


MY = _build_my_palette()
```

Главное — плавные переходы без разрывов, иначе на ленте будут видны «полосы».

## ✨ Эффекты (`effects.py`)

Все эффекты имеют единую сигнатуру:

```python
def fill_xxx(buf, pal, n, xs, t, o):
    ...
```

| Параметр | Что это |
| :--- | :--- |
| `buf` | bytearray буфера neopixel (`strip.buf`) |
| `pal` | палитра (bytes, 256×3) |
| `n` | число LED |
| `xs` | масштаб (`X_SCALE`) |
| `t` | координата времени (frame counter) |
| `o` | кортеж `ORDER`: `(1,0,2,3)` = GRB |

### Каталог эффектов

| Эффект | Что делает | Идеальные палитры |
| :--- | :--- | :--- |
| **`fill_flame`** | Классическое пламя: позиция × время | FIRE, ICE, ARCANE, PLASMA |
| **`fill_flame_octaves`** | Пламя с двумя октавами — больше деталей | FIRE, BLOOD, VOLCANO |
| **`fill_flame_wind`** | Пламя качается на «ветру» | FIRE, CANDLE |
| **`fill_twinkle`** | Пламя + случайные искры | FIRE, ARCANE, GOLD |
| **`fill_comet`** | Комета с шумовым хвостом | AURORA, SUNSET, ICE |
| **`fill_rainbow_flow`** | Радуга течёт по ленте | **только RAINBOW!** |
| **`fill_aurora`** | Северное сияние: две медленные волны | AURORA, OCEAN, GHOST |
| **`fill_pulse`** | Вся лента дышит синхронно | PLASMA, SUNSET, GOLD |
| **`fill_lightning`** | Редкие яркие вспышки на тёмном фоне | TOXIC, NEON |
| **`fill_fireflies`** | Светлячки: разбросанные точки с разными ритмами | GHOST, ARCANE |

### Как создать свой эффект

Добавьте функцию в `effects.py`:

```python
def fill_my_effect(buf, pal, n, xs, t, o):
    o0, o1, o2 = o
    for i in range(n):
        v = uperlin8(i * xs, t)          # ваша логика шума
        idx = v * 3
        pos = i * 3
        buf[pos + o0] = pal[idx]
        buf[pos + o1] = pal[idx + 1]
        buf[pos + o2] = pal[idx + 2]
```

И используйте в `config.py` как `EFFECT = effects.fill_my_effect`.

## 🧠 Как это работает

### Шум Перлина в двух словах

Шум Перлина генерирует плавные, но «случайные» значения. В отличие от `random()`, соседние значения тесно связаны — это создаёт естественные градиенты, идеально подходящие для органических эффектов.

### Реализация

1. **Таблица перестановок** — классическая 256-элементная таблица Кена Перлина. «Хеширует» координаты в псевдослучайные градиенты.
2. **Целочисленная арифметика** — вся математика (интерполяция, градиенты) в 8-битных числах с wrap-around, как в оригинальном `uPerlin`.
3. **Viper-компиляция** — декоратор `@micropython.viper` превращает Python-функции в машинный код для Xtensa/RISC-V. Даёт 10–30x ускорение.
4. **Ease-интерполяция** — квадратичная функция сглаживает переходы между «ячейками» шума.
5. **Прямой доступ к буферу** — `strip.buf` даёт `bytearray`, куда библиотека пишет напрямую. Мы заполняем его без создания кортежей `(r, g, b)`.

### Почему 2D, а не 1D?

1D-шум даёт «статичный» паттерн. Чтобы эффект «жил», нужна **вторая координата — время**:

```python
v = uperlin8(i * X_SCALE, time_coord)
#              ^позиция     ^время
```

При каждом кадре `time_coord` увеличивается, и паттерн плавно «прокручивается» вдоль второй оси шума.

- **`main.py`** — 7 строк, просто вызывает `benchmark()` и `main()`.

## ❓ Частые вопросы

### Цвета неправильные (зелёное вместо красного)

Порядок байтов в `strip.buf` зависит от прошивки. Стандарт для WS2812 — **GRB**, но встречаются **RGB**-варианты. Код автоматически берёт `strip.ORDER`, если он доступен. Если цвета всё равно неправильные — проверьте в REPL:

```python
import neopixel, machine
s = neopixel.NeoPixel(machine.Pin(5), 1)
print(s.ORDER)  # (1, 0, 2, 3) = GRB, (0, 1, 2, 3) = RGB
```

Если `strip.ORDER` отсутствует — поменяйте местами `o0` и `o1` в `_ORDER` в `app.py`.

### `AttributeError: 'NeoPixel' object has no attribute 'buf'`

Ваша прошивка MicroPython старше 1.20. Обновите её с [официального сайта](https://micropython.org/download/ESP32_GENERIC/).

### Viper падает с `ViperTypeError`

Viper требует, чтобы все операнды в выражении были одного типа (`int`). Если смешиваете Viper-`int` с обычным Python-объектом — получите ошибку. Решение: явно приводите через `int(...)` в **обычном** (не-Viper) коде перед передачей в Viper-функцию.

### Ctrl-C не прерывает программу

Это ограничение Viper: во время выполнения Viper-функции прерывание с клавиатуры недоступно. Если программа «зависла» — жмите **reset** на плате.

### Эффект меняется при перезагрузке

Эффекты `fill_twinkle` и `fill_lightning` используют `random`, который в MicroPython на ESP32 **автоматически сидируется аппаратным ГПСЧ**. Чтобы зафиксировать последовательность, добавьте в `config.py` или `app.py`:

```python
import random
random.seed(42)
```

### Шум «рваный», видны скачки

Уменьшите `TIME_STEP` до `1` и/или увеличьте `FRAME_MS` до `40–50`.

### Пламя выглядит «однородным», нет языков

Увеличьте `X_SCALE` в 10–20 раз (до `800–1500`). Значение по умолчанию `60` даёт одну очень широкую волну.

### LED мерцают / глючат

- Проверьте питание: 150 LED при полной яркости едят до 9А.
- Поставьте резистор 330–470 Ом на линии данных.
- Поставьте конденсатор 1000 мкФ на питании ленты.
- Убедитесь, что земля ESP32 и ленты соединены.
- Для длинных лент (>300 LED) используйте level shifter.

### Работает ли на ESP32-S3 / C3?

Да. Viper поддерживается на всех архитектурах, включая Xtensa (ESP32, S2, S3) и RISC-V (C3, C6). Разница — абсолютные цифры производительности (S3 быстрее, C3 медленнее).

Если понадобится больше:

- **Viper-fill** — вынести заполнение буфера в `@micropython.viper`-функцию. Даёт ещё ~30% скорости.
- **Предвычисленная таблица** — генерировать массив RGB на старте и «прокручивать» его. Максимальная экономия CPU, но эффект становится циклическим.
- **C-модуль** — если понадобится 2D-матрица с высоким разрешением. Требует пересборки прошивки ESP-IDF.
- **Смешивание 3+ октав шума** — для ещё более реалистичного пламени.
- **16-битные версии** (`uperlin16`) — для градиентных эффектов на очень длинных лентах.

## 🤝 Совместимость с оригиналом

Реализация портирована из [GyverLibs/uPerlin](https://github.com/GyverLibs/uPerlin), который основан на коде из FastLED.

Оригинальный C++ API:

```cpp
uint8_t uperlin8(uint16_t x);
uint8_t uperlin8(uint16_t x, uint16_t y);
uint16_t uperlin16(uint32_t x);
uint16_t uperlin16(uint32_t x, uint32_t y);
```

Наш порт реализует **8-битные версии**. Для LED-ленты 8 бит (256 уровней) более чем достаточно.

**Визуальное поведение идентично**: те же коэффициенты интерполяции, та же таблица перестановок, та же логика градиентов.
